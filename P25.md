# P25 Phase I control-data receiver

Release checkpoint: **0.16.0-preview1** includes the identifier and expanded-control milestones below. The channel and expanded-control generated samples are now bundled under Docs/Samples. Source-only/preview3 notes below describe earlier development checkpoints. Live acceptance of the additions remains pending.

Windows receive-only preview. Enable **P25 Phase I (C4FM)** in the Data tab, separately from AX.25/APRS. This first decoder uses the NFM discriminator from SDR I/Q or M.R.S. I/Q replay. Listening volume, mute and RF squelch do not gate decoding. Each receiver has independent enable settings, decoder state and history.

## Data readability update — source addition after 0.15.0-preview1

**Group P25 repeats** is enabled by default and saved per receiver. Site and network status update their existing rows as fields change. NID headers group by decoded identity despite corrected raw-bit differences. Undecoded standard/manufacturer/protected TSBKs group by opcode/manufacturer category; changing payloads update the latest bytes and content-change count. These are category summaries, not claims of identical payloads. Identical grants are counted; different grants remain separate. Grouping separates receiver/source session, live versus replay, frequency, NAC and message kind.

Last seen UTC and Count update in place. Selected details include first/last seen, reception count, content-change count and the latest raw bytes. These are retained observations, not a live/stale guarantee; last-seen timestamps remain visible after reception stops. User-selected sorting can change the initial row order, but repeated updates do not remove/reinsert the row. Site/network rows are preferentially retained when activity rows reach the 500-summary-row limit.

Uncheck the grouping option to inspect the latest 500 individual observations. Both views are maintained while receiving; toggling does not reconstruct lifetime counts from the shorter history. Clear resets both. JSON export follows the visible view and active filter. Summary exports retain the usual observation fields plus `ReceptionCount`, `FirstSeenUtc` and `ContentChanges`; `ObservedUtc` is the latest observation time. Previous content is available only while retained in individual-message history; the summary is not a permanent audit log.

The grouping and layout changes shipped in 0.15.0-preview3, which the user accepted on October 3, 2026. The user's September 30 screenshot shows verified NAC 345 headers and CRC-valid network/site messages; this is evidence of local reception, not a complete acceptance test of all P25 formats or fields.

The divider between the Data list and selected-message details is now an eight-pixel horizontal drag handle. Drag vertically to allocate space; it also supports arrow keys when focused. The default gives the list two thirds of the flexible space, with minimum heights to keep both panels accessible. The split lasts for the open window and is not yet saved across restarts. Session diagnostics have moved to a separate **Session log** tab so the main spectrum/waterfall can use the freed space.

After review of the crowded minimum-size screenshot, decoder checkbox captions were shortened to AX.25 / APRS, P25 Phase I and CTCSS / DCS; their tooltips retain the mode/input details. Counters and explanatory text are under **Decoder status and help**, collapsed initially. Expand it to inspect decoder state, counts or input requirements; the expanded area scrolls within a height limit. This reserves the compact window's space for message rows and selected details. The minimum-size visual check now includes multiple P25 summary rows rather than only a single DCS observation.

## Implemented

- 4,800-symbol/s C4FM acquisition with ten symbol-phase hypotheses, sync-derived DC/level correction and polarity handling. Capture is reduced to a 48 kHz discriminator stream before listening-audio filtering.
- Frame sync, status-symbol removal and conservative BCH network-identifier validation with at most four corrected bits. A validated NID supplies NAC and DUID; it does not validate the payload.
- One, two or three TSBK control blocks: deinterleaving, rate-1/2 hard-decision trellis decoding and mandatory CRC validation. Trellis paths above a bounded error metric are rejected.
- Standard manufacturer ID 00 messages: network status (WACN/system/channel ID), RFSS/site status and group voice channel grants (talkgroup/source/channel ID/service options).
- Other CRC-valid opcodes and manufacturer formats retain raw bytes and their identifiers. Protected blocks are labeled without interpreting their fields as cleartext.
- Data history, filtering, selection details and JSON export retain protocol, UTC observation time, frequency and replay attribution. NID entries explicitly say **header only**; control messages say **TSBK CRC valid**. Failed candidates never become trusted P25 data rows.
- Bounded pending queue (256) and shared Data history (500); overflow is counted. Retuning, source changes, replay seeks/gaps and stopping reset decoder state. Counters accumulate until Clear.

## Current limits

This preview is tested with independently generated protocol vectors and synthetic C4FM I/Q, not a local off-air P25 recording. It has no CQPSK/LSM equalizer, P25 voice audio, Phase II decoder, encryption-key support, automatic trunk following, MBT parser or complete TSBK message dictionary. Some simulcast systems will not decode through this C4FM path. Recognizing a voice-frame header does not decode its voice payload.

Channel IDs remain hexadecimal identifiers. The source update below resolves supported messages only after a matching identifier table is received. The FrequencyHz attached to each observation remains the monitored input frequency; resolved channels are separate P25Channel fields.

Generic microphone/speaker audio is not enabled for P25 in this preview. A separate validated flat-discriminator/data-audio input remains planned. Existing conventional-radio audio support for other modes is retained.

## Acceptance test

1. Extract the entire runtime ZIP into a new folder and launch MRS.exe. Existing station settings and saved frequencies remain in the application-data folder.
2. Select your SDR, tune a known P25 Phase I **C4FM** control channel, select NFM and a 12.5 or 16 kHz channel bandwidth. Use normal receiver gain/tuning settings; the spectrum alone does not establish protocol identity.
3. Open Data and check **Enable P25 Phase I (C4FM)**. AX.25 can stay off. Look for verified headers and CRC messages, NAC, WACN/system and site details where those messages are broadcast.
4. Select rows to inspect complete fields and raw bytes. Filter by P25, NAC, WACN or talkgroup text; export JSON and verify the displayed frequency/source.
5. Mute listening or close squelch and confirm decoding continues. Retune away and back, then replay a recorded I/Q sample. Confirm no partial message is joined across the boundary. Repeat on Receiver B if desired.
6. A supplied **synthetic-p25-control.mrsiq** test file can exercise the feature without RF hardware. Expected: NAC 293, WACN ABCDE, system 123, RFSS 2, site 3, talkgroup 4660 and source 74565. All identities and activity in that file are artificial. Replay should produce 8 headers and 24 CRC-valid messages after Clear; the fixture is less than one second long.

Zero CRC messages is not evidence that the channel lacks P25. Record the input and report mode, bandwidth, center/channel frequency and whether the site uses simulcast. Live RF acceptance remains pending.

## Identifier-update channel frequencies — October 3 source milestone

Receives standard manufacturer 00, unprotected, CRC-valid IDEN_UP (3D), IDEN_UP_VU (34), and IDEN_UP_TDMA (33) over the existing Phase I C4FM path. These become **Identifier update** rows showing band ID, base, spacing, offset, bandwidth where known, and access/slot details. Grouping updates a fixed row per band ID instead of mixing distinct tables. Message-type visibility includes this category.

Network/site status and existing group voice grants now append downlink and available uplink frequencies. TDMA table types 0–5 use their defined carrier/slot mapping; the displayed slot is explicitly zero-based. Decoding TDMA allocation metadata does not add Phase II voice reception. Channel number FFFF, absent tables, zero base/spacing, and reserved channel types remain explicitly unresolved. A no-uplink offset indicator does not become a made-up transmit frequency.

Tables are receiver-local, limited to 16 identifiers for the current NAC, and reset on source/tuning changes, replay gaps, stop, disable, Clear, and observed changes of NAC/system/site identity. A changed valid identifier replaces that ID's earlier table. Protected, manufacturer-specific, or CRC-failed updates cannot populate tables. Unresolved historical messages are not rewritten after learning a table: subsequent received status/grant messages use it. Retained rows still represent past observations; check last-seen time.

JSON adds optional P25BandPlan and P25Channel objects, with integer Hz values and nullable unresolved fields. Existing FrequencyHz remains the input frequency. Hidden identifier messages still update the decoder's tables; display filters do not gate interpretation. No automatic tuning, frequency-library writes, or voice following is introduced.

## Expanded standard control messages — October 3 source milestone

Added unprotected, standard MFID 00, CRC-validated TSBK formats:

| Opcode (hex) | Data type | Decoded content |
| --- | --- | --- |
| 02 | Group voice grant update | Up to two talkgroup/channel assignments; each channel resolves independently, including TDMA slots |
| 03 | Explicit group voice grant | Talkgroup, service options, separate downlink/uplink channel IDs |
| 39 | Secondary control channels | RFSS/site and advertised alternate control channels with raw service-class values |
| 3C | Adjacent site status | Advertised system/RFSS/site, LRA, flags, service class and control channel |

The existing 00 grant now also exports a structured assignment containing its source-radio ID and service options. Formats that do not supply those fields leave them null. Each received TSBK remains one observation; a dual grant is not counted as two received packets. Identical/unused B assignments are suppressed in the structured interpretation, while the complete raw bytes are retained. Distinct channels/slots remain separate assignments even when they share a carrier or talkgroup. Secondary B entries with zero service class or an identical channel ID are not presented as an extra channel.

Explicit uplink IDs are resolved through their own table's base/spacing/slot mapping, not by adding the downlink's implicit offset. Missing uplink tables remain explicitly unresolved, even when the downlink table offers an implicit offset. Missing downlink tables do not erase an independently resolvable explicit uplink.

Adjacent-site announcements describe neighbors; they do not replace the monitored site's identity or clear its tables. Their flags/service-class bytes are shown as advertised values, without claiming verified reachability or live call state. Different neighbors get distinct grouped rows; changed fields update the matching neighbor row. Secondary announcements group by advertised RFSS/site and channel-ID set, preserving different alternate-channel sets. These are bounded observation summaries, not yet a persistent system database.

The four types are individually selectable in **P25 message types**. The grants/status preset includes all three group-grant formats and current site/network status, while hiding neighbor, secondary-channel, identifier, and routine header/undecoded categories. Existing saved selections are retained; use the preset again to apply the expanded selection.

JSON adds `P25Assignments` and `P25SiteAnnouncement`. The earlier `P25Channel` field is the first/primary channel for compatibility; use the new arrays to retrieve every assignment or secondary channel. Explicit channel results add `UplinkChannelId` and `UplinkResolution`. No channel following, voice playback, radio alias lookup, or automatic frequency-library modification is included.
